# Deploy the agent to an existing Foundry project

[deploy-agent.ps1](./deploy-agent.ps1) reads the repository-root `.env` using
[the shared helpers](../common-scripts/Common.ps1), like the prerequisite scripts.
It does not read the root file relative to your current working directory.
Explicit parameters override saved values; `-EnvFile` selects another file.

## Inputs

Add these values to the root `.env` without replacing your existing configuration.
See the dedicated **deployment** group in [the root template](../.env.v1.example),
between prerequisite 7 and post-requisite 1. `AZURE_TENANT_ID` is defined once in
the prerequisite 4 group and reused here.

```dotenv
AZURE_ENV_NAME="atlassian-env"
AZURE_TENANT_ID="<tenant GUID>"
AZURE_LOCATION="swedencentral"
AZURE_FOUNDRY_PROJECT_RESOURCE_ID="/subscriptions/<subscription GUID>/resourceGroups/<group>/providers/Microsoft.CognitiveServices/accounts/<account>/projects/<project>"
AZURE_FOUNDRY_PROJECT_ENDPOINT="https://<account>.services.ai.azure.com/api/projects/<project>"
AZURE_BOT_SERVICE_RESOURCE_ID=""
FOUNDRY_MODEL_NAME="gpt-5.6-luna"
GATEWAY_MODELS_ENDPOINT="<model gateway endpoint>"
GATEWAY_SUBSCRIPTION_KEY="<model gateway subscription key>"
APIM_STATUS_SUBSCRIPTION_KEY=""
APIM_MCP_SUBSCRIPTION_KEY=""
AZURE_BOT_SERVICE_OAUTH_CONNECTION_NAME="<Bot Service OAuth connection name>"
```

The subscription, resource group, account and project are derived from the
existing project ARM ID, not duplicated as deployment inputs. The endpoint must
match that ID. Use the actual project's region.

Only these mappings are injected into the selected azd environment:

| Root source | azd variable / use |
|---|---|
| `AZURE_ENV_NAME` | Selects/creates the local azd environment; passed as `--environment` |
| `AZURE_TENANT_ID` | `AZURE_TENANT_ID` |
| `AZURE_LOCATION` | `AZURE_LOCATION` and the location used by `azd env new` |
| `AZURE_FOUNDRY_PROJECT_RESOURCE_ID` | `AZURE_AI_PROJECT_ID` |
| Subscription segment of the project ARM ID | `AZURE_SUBSCRIPTION_ID` |
| Resource-group segment of the project ARM ID | `AZURE_RESOURCE_GROUP` |
| `AZURE_FOUNDRY_PROJECT_ENDPOINT` | `FOUNDRY_PROJECT_ENDPOINT` |
| `FOUNDRY_MODEL_NAME` (defaults to `gpt-5.6-luna` when missing/empty) | `FOUNDRY_MODEL_NAME` |
| `GATEWAY_MODELS_ENDPOINT` | `GATEWAY_MODELS_ENDPOINT` |
| `GATEWAY_SUBSCRIPTION_KEY` | `GATEWAY_SUBSCRIPTION_KEY` |
| `AZURE_APIM_MCP_SERVER_URL` (generated by prerequisite 7) | `APIM_MCP_URL` |
| `AZURE_APIM_CONNECT_STATUS_URL` (generated by prerequisite 7) | `ATLASSIAN_STATUS_URL` |
| `APIM_STATUS_SUBSCRIPTION_KEY` | `APIM_STATUS_SUBSCRIPTION_KEY` |
| `APIM_MCP_SUBSCRIPTION_KEY` | `APIM_MCP_SUBSCRIPTION_KEY` |
| `AZURE_BOT_SERVICE_OAUTH_CONNECTION_NAME` | `AGENTAPPLICATION__USERAUTHORIZATION__HANDLERS__APIM__SETTINGS__AZUREBOTOAUTHCONNECTIONNAME` |

Agent settings are declared under `services.agent.env` in
[azure.yaml](./azure.yaml). The script resolves the model default and sets every
listed agent setting in azd before validation/deployment. No duplicate root
`APIM_MCP_URL`, `ATLASSIAN_STATUS_URL` or long handler-name input is needed.
Run prerequisite 7 first to save the two APIM URLs. The model gateway endpoint,
model gateway subscription key and OAuth connection name must be nonempty.
The connection name is injected only; [post-requisite 1](../post-requisites/README.md)
configures the Bot Service OAuth connection using that same name.

The two APIM agent subscription keys are optional deployment inputs. Missing
or empty keys explicitly clear their azd settings, including in reused
environments, rather than retaining old credentials. The APIs still enforce
`Ocp-Apim-Subscription-Key`; calls without a valid key will be rejected.
Use real subscription keys in the ignored root `.env`, never in the example.
azd stores injected values in its local environment file; protect that file
as you would the root `.env`.

The APIM subscription/resource group from prerequisites are not substituted for
the Foundry project's derived values. `AZURE_BOT_SERVICE_RESOURCE_ID` is an
optional deployment verification/discovery input, not an azd variable.
Do not add duplicate root `AZURE_AI_PROJECT_ID`, `FOUNDRY_PROJECT_ENDPOINT` or
`AZURE_RESOURCE_GROUP` assignments; those are azd-side names.

The single source of truth for the deployed agent name is
`services.agent.name` in [azure.yaml](./azure.yaml). Edit that literal
value to rename the agent; the service key `agent` remains unchanged.
The script parses YAML, requires an explicit string name and rejects duplicate
keys and environment substitutions. It ignores any previously saved
`AZURE_FOUNDRY_AGENT_NAME` and no longer accepts `-AgentName`.
After successful deployment and verification, it saves the manifest's name as
`AZURE_FOUNDRY_AGENT_NAME` under **Generated by deployment** at the bottom of
the root environment. It does not appear in the example. A new name targets a different
agent; it does not rename or delete the old Azure agent.

Leave the bot ID empty for discovery in the project's resource group. If there
are multiple bots with the agent identity, or your bot lives in a different
resource group, provide its ARM ID explicitly. A saved bot ID is validated, not
silently replaced. To rediscover a bot after deliberately changing the agent,
pass `-BotServiceArmId ''`.

## Run

Install the local YAML parser once using the same `python` on PATH that the
script uses (this is a deployment-tool dependency, not an agent runtime dependency):

```powershell
python -m pip install -r .\agent-deployment\requirements-deploy.txt
```

Authenticate both CLIs before running: `azd auth login --tenant-id <tenant GUID>`
for deployment and `az login --tenant <tenant GUID>` for resource verification.
Your account needs agent deployment rights, bot/resource read access, and any
permissions required by the deployment extension to create/configure its bot.
Private projects require working private DNS and network connectivity.

From the repository root:

```powershell
.\agent-deployment\deploy-agent.ps1 -WhatIf
.\agent-deployment\deploy-agent.ps1
```

The script:

1. Validates configuration and the Azure CLI tenant.
2. Creates the named local azd environment if absent, or reuses it. An existing
   environment bound to another project, subscription or tenant is rejected;
   choose a new environment name rather than repointing it.
3. Sets the deployment variables, runs `azd ai agent doctor --local-only` and,
   if validation passes, runs `azd deploy agent` from the deployment
   folder. It does not run `init`, `provision` or `up`.
4. Reads the deployed agent, finds its bot by client ID and tenant, and checks the
   bot messaging endpoint using the same validation as the post-requisites.
   Discovery uses core `az resource list` plus ARM GET, not the bot CLI extension.
5. Atomically saves the verified inputs needed for post-requisites:
   `AZURE_FOUNDRY_PROJECT_ENDPOINT`, `AZURE_FOUNDRY_AGENT_NAME`, and
   `AZURE_BOT_SERVICE_RESOURCE_ID`. It also saves the effective environment name,
   tenant, location and project ID so parameter overrides persist.

Unrelated configuration and credentials are preserved. No backup file is read or
modified. Only explicitly selected deployment values are copied into azd; the
script does not copy Atlassian secrets or dump all environment values.

`-WhatIf` performs local validation, including parsing YAML with Python: no
az/azd calls, Azure changes, environment creation or file writes.
Normal runs request confirmation; reviewed automation
can use `-Confirm:$false`.

A failed CLI operation or verification stops the script without saving root
configuration. Earlier successful azd/Azure changes are not rolled back. Correct
the reported issue and rerun; an existing matching azd environment is reused.
Successful deployment output is not printed. Failures identify the operation and
exit code and include azd's diagnostic output, redacting known secret values from
the root/azd/process environments and common credential fields. Review diagnostics
before sharing; arbitrary application output can still contain sensitive data
that these patterns cannot identify. Long diagnostics retain the last 12,000
characters after redaction. Non-JSON azd progress output is not treated as JSON.

After success, run [post-requisite 1](../post-requisites/README.md) to configure
the bot's OAuth connection, then step 2 to configure the M365 endpoint/channel.
Step 3 prepares a ZIP offline for manual Teams admin center upload. Deployment
verification does not enable the public Activity exception, upload an app,
prove Teams delivery, or configure Atlassian OAuth consent.

## Tests

```powershell
$result = Invoke-Pester -Script .\agent-deployment\Tests -PassThru
if ($result.FailedCount -gt 0) { throw 'Deployment tests failed.' }
```

Tests use temporary environment files and mocked CLIs; they never deploy to Azure.
